# 오늘 배운 ROS 2 패키지 실습 간단 정리

## 1. 오늘 무엇을 배웠는가?

오늘은 단순히 Python 파일 하나를 실행한 것이 아니라, **Python 코드를 ROS 2가 인식하고 관리하고 실행할 수 있는 정식 패키지 형태로 만드는 과정**을 배웠다.

전체 흐름은 다음과 같다.

```text
ROS 2 환경 불러오기
        ↓
워크스페이스 생성
        ↓
ROS 2 Python 패키지 생성
        ↓
실행할 노드 코드 작성
        ↓
의존성과 실행 방법 등록
        ↓
패키지 빌드
        ↓
환경 적용
        ↓
노드 실행 및 확인
```

현재 만든 패키지는 실제 모터나 센서를 제어하는 완성 프로그램은 아니지만, 앞으로 기능을 추가할 수 있는 **최소 동작 ROS 2 패키지**이다.

---

## 2. 워크스페이스 생성

```bash
mkdir -p ~/ros2_ws/src
```

- `ros2_ws`는 ROS 2 프로젝트 전체 작업 공간이다.
- `src`는 사용자가 직접 작성한 패키지와 원본 코드를 저장하는 폴더이다.
- `-p` 옵션은 바깥쪽 폴더가 없으면 먼저 만들고, 이미 존재하면 오류 없이 넘어가도록 한다.

빌드 후에는 다음 폴더가 자동으로 생긴다.

```text
ros2_ws/
├── src/       # 원본 코드
├── build/     # 빌드 중간 파일
├── install/   # 실행 가능한 설치 결과
└── log/       # 빌드 기록
```

---

## 3. ROS 2 환경 적용

```bash
source /opt/ros/humble/setup.bash
```

설치된 ROS 2 Humble 명령어와 패키지를 현재 터미널에서 사용할 수 있도록 한다.

```bash
source ~/ros2_ws/install/setup.bash
```

내가 직접 빌드한 `ros2_ws`의 패키지를 현재 터미널이 찾을 수 있도록 한다.

즉 다음과 같이 구분할 수 있다.

```text
/opt/ros/humble/setup.bash
→ 기본 ROS 2 환경 적용

~/ros2_ws/install/setup.bash
→ 내가 만든 패키지 환경 적용
```

---

## 4. 패키지 생성

```bash
cd ~/ros2_ws/src

ros2 pkg create   --build-type ament_python   --dependencies rclpy   --license Apache-2.0   my_robot_controller
```

이 명령으로 다음 조건의 패키지를 만들었다.

```text
패키지 이름     : my_robot_controller
사용 언어       : Python
빌드 방식       : ament_python
필요한 의존성   : rclpy
라이선스        : Apache-2.0
```

### 패키지란?

패키지는 ROS 2 프로그램을 기능별로 묶어 관리하는 단위이다.

예를 들어 실제 로봇 프로젝트에서는 다음처럼 나눌 수 있다.

```text
camera_package       → 카메라 처리
motor_package        → 모터 제어
temperature_package  → 온도 분석
alarm_package        → 경고 처리
```

---

## 5. 의존성이란?

의존성은 **내 프로그램이 실행되기 위해 필요한 다른 라이브러리나 패키지**를 의미한다.

내 코드에서는 다음과 같이 `rclpy`를 사용한다.

```python
import rclpy
from rclpy.node import Node
```

따라서 `rclpy`가 없으면 이 코드는 실행되지 않는다.

```text
내 Python 코드
        ↓ 필요함
      rclpy
```

패키지 생성 시 다음 옵션을 지정한 이유가 이것이다.

```bash
--dependencies rclpy
```

이 옵션을 사용하면 `package.xml`에 다음 내용이 자동으로 등록된다.

```xml
<depend>rclpy</depend>
```

이는 ROS 2에게 다음 내용을 알려준다.

> 이 패키지를 빌드하거나 실행하려면 rclpy가 필요합니다.

의존성을 실제로 확인하고 설치할 때는 다음 명령을 사용한다.

```bash
rosdep install --from-paths src --ignore-src -r -y
```

- `--from-paths src`: `src` 안의 패키지를 확인한다.
- `--ignore-src`: `src` 안에 이미 있는 패키지는 설치 대상에서 제외한다.
- `-r`: 일부 문제가 있어도 가능한 범위까지 계속 진행한다.
- `-y`: 설치 질문에 자동으로 동의한다.

---

## 6. rclpy란?

`rclpy`는 Python 프로그램이 ROS 2 기능을 사용할 수 있도록 해주는 라이브러리이다.

대표 기능은 다음과 같다.

- 노드 생성
- 다른 노드에 데이터 전송
- 다른 노드의 데이터 수신
- 서비스 요청과 응답
- 반복 작업 실행
- 로그 출력
- ROS 2 통신 시작과 종료

즉, 일반 Python 프로그램을 ROS 2 프로그램으로 동작하게 해주는 연결 도구라고 볼 수 있다.

## 7. controller_node.py 작성

실제 실행할 Python 노드 파일을 생성하였다.

```bash
nano ~/ros2_ws/src/my_robot_controller/my_robot_controller/controller_node.py
```

작성한 핵심 코드는 다음과 같다.

```python
import rclpy
from rclpy.node import Node


class RobotController(Node):

    def __init__(self):
        super().__init__('robot_controller')
        self.get_logger().info('controller_node가 실행되었습니다.')


def main(args=None):
    rclpy.init(args=args)
    node = RobotController()

    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        node.get_logger().info('사용자 요청으로 노드를 종료합니다.')
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

### 코드 흐름

```text
rclpy.init()
→ ROS 2 통신 시작

RobotController()
→ robot_controller 노드 생성

rclpy.spin(node)
→ 노드를 계속 실행하며 대기

Ctrl+C
→ 실행 중단

destroy_node(), shutdown()
→ 노드와 ROS 2 통신을 안전하게 종료
```

## 8. setup.py 수정

`controller_node.py` 파일만 만들어서는 `ros2 run` 명령으로 실행할 수 없다.

ROS 2가 실행 파일을 찾도록 `setup.py`에 다음 내용을 등록하였다.

```python
entry_points={
    'console_scripts': [
        'controller_node = my_robot_controller.controller_node:main',
    ],
},
```

이 한 줄의 의미는 다음과 같다.

```text
controller_node
→ ros2 run에서 입력할 실행 이름

my_robot_controller.controller_node
→ controller_node.py 파일

main
→ 파일 안에서 실행할 함수
```

그래서 다음 명령을 사용할 수 있게 된다.

```bash
ros2 run my_robot_controller controller_node
```

## 9. package.xml의 역할

`package.xml`은 ROS 2 패키지의 설명서이자 필요한 준비물 목록이다.

주요 내용은 다음과 같다.

- 패키지 이름
- 버전
- 설명
- 관리자
- 라이선스
- 필요한 의존성
- 테스트 의존성
- 빌드 방식

예시:

```xml
<name>my_robot_controller</name>
<depend>rclpy</depend>

<export>
  <build_type>ament_python</build_type>
</export>
```

쉽게 말하면 ROS 2에게 다음 정보를 알려주는 파일이다.

> 이 패키지는 my_robot_controller이고, rclpy가 필요하며, ament_python 방식으로 빌드합니다.

## 10. setup.cfg와 resource

### setup.cfg

Python 실행 스크립트를 설치할 위치를 지정한다.

```ini
[develop]
script_dir=$base/lib/my_robot_controller

[install]
install_scripts=$base/lib/my_robot_controller
```

### resource

```text
resource/
└── my_robot_controller
```

ROS 2의 패키지 색인에 `my_robot_controller` 패키지가 존재한다는 것을 등록하는 이름표 역할을 한다.

---

## 11. ament_python과 colcon

### ament_python

Python으로 만든 ROS 2 패키지를 설치하는 빌드 방식이다.

```text
ament_cmake   → C++ 패키지
ament_python  → Python 패키지
```

`setup.py`, `setup.cfg`, `package.xml` 등의 정보를 사용한다.

### colcon

워크스페이스 안의 패키지를 실제로 빌드하는 도구이다.

```bash
colcon build --symlink-install --packages-select my_robot_controller
```

- `--symlink-install`: 원본 Python 파일과 설치 결과를 심볼릭 링크로 연결한다.
- `--packages-select`: 지정한 패키지만 빌드한다.

심볼릭 링크는 원본 파일을 가리키는 리눅스식 바로가기이다.

## 12. 패키지 빌드

```bash
cd ~/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-select my_robot_controller
source install/setup.bash
```

빌드 성공 결과:

```text
Starting >>> my_robot_controller
Finished <<< my_robot_controller

Summary: 1 package finished
```

이는 패키지가 ROS 2에서 실행 가능한 형태로 정상적으로 설치되었다는 뜻이다.

## 14. 노드 실행과 확인

첫 번째 터미널에서 실행한다.

```bash
ros2 run my_robot_controller controller_node
```

정상 출력:

```text
[INFO] [robot_controller]: controller_node가 실행되었습니다.
```

노드 실행 중에는 첫 번째 터미널이 계속 사용 중이므로, 두 번째 터미널을 열어 확인한다.

```bash
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash
ros2 node list
```

정상 결과:

```text
/robot_controller
```

### 두 이름의 차이

```text
controller_node
→ ros2 run에서 사용하는 실행 이름

robot_controller
→ ROS 2 내부에 등록된 노드 이름
```

노드를 종료할 때는 첫 번째 터미널에서 `Ctrl+C`를 누른다.

## 15. 빌드와 실행의 차이

```text
colcon build
→ 프로그램을 실행할 수 있도록 준비하고 설치함

ros2 run
→ 빌드된 프로그램을 실제로 실행함

ros2 node list
→ 현재 실행 중인 노드를 확인함
```

따라서 빌드만 하고 `ros2 node list`를 실행하면 아무것도 나오지 않는 것이 정상이다.

## 16. tree 명령

```bash
tree src
```

`src` 폴더 아래의 모든 하위 폴더와 파일을 끝까지 보여준다.

```bash
tree -L 2
```

현재 위치를 기준으로 2단계까지만 보여준다.

```text
tree src
→ src 내부 상세 구조 확인

tree -L 2
→ 워크스페이스 전체의 큰 구조 확인
```

## 17. __pycache__란?

Python 노드를 실행하면 다음 폴더가 자동으로 생길 수 있다.

```text
__pycache__/
├── controller_node.cpython-310.pyc
└── __init__.cpython-310.pyc
```

이는 Python이 프로그램을 빠르게 다시 실행하기 위해 만든 캐시 파일이다.

- `.py`: 직접 작성한 원본 코드
- `.pyc`: Python이 자동 생성한 캐시

직접 수정할 필요가 없으며, 삭제해도 다시 실행하면 자동으로 생성된다.

## 18. 왜 ROS 2 패키지가 필요한가?

작은 Python 프로그램은 다음처럼 직접 실행할 수 있다.

```bash
python3 controller_node.py
```

하지만 실제 로봇은 여러 프로그램이 동시에 동작한다.

```text
카메라 노드
온도 분석 노드
모터 제어 노드
알람 노드
DB 저장 노드
```

ROS 2 패키지로 만들면 다음 장점이 있다.

- 기능별로 코드를 정리할 수 있다.
- 필요한 의존성을 기록할 수 있다.
- `ros2 run`으로 쉽게 실행할 수 있다.
- 여러 패키지의 빌드 순서를 자동으로 관리할 수 있다.
- 다른 노드와 데이터를 주고받을 수 있다.
- 다른 컴퓨터나 Jetson으로 옮기기 쉽다.
- GitHub에서 다른 사람과 공유하기 쉽다.

## 19. 오늘 실습의 최종 의미

오늘 만든 것은 완성된 로봇 제어 기능이 아니라, 실제 로봇 기능을 넣기 위한 기본 골격이다.

현재 노드의 기능은 다음과 같다.

```text
ROS 2 통신 시작
        ↓
robot_controller 노드 생성
        ↓
실행 로그 출력
        ↓
계속 실행하며 대기
        ↓
Ctrl+C로 종료
```

앞으로 이 패키지에 다음 기능을 추가할 수 있다.

```text
Publisher와 Subscriber
센서 데이터 처리
모터 제어
카메라 영상 처리
온도 분석
위험 단계 판정
DB 저장
알람 전송
```
